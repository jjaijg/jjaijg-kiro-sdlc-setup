# SDLC Automation — Phase 1: Analysis Workflow Guide

## Actors
| Actor | Role |
|-------|------|
| BA    | Business Analyst — drives the analysis phase |
| PO    | Product Owner — reviews and approves via PR |

---

## Prerequisites
- `gh` GitHub CLI installed and authenticated (`gh auth login`)
- Git configured with remote `origin` pointing to your GitHub repo
- Kiro IDE open on this workspace

---

## Phase 1A — Epic Generation & Approval

### Step 1 · BA generates epics
In Kiro chat:
```
/sdlc-analyst #File:docs/brds/pbp-current-account-brd.md generate epics
```
The agent activates **Epic Writer**, analyses the BRD, and creates:
`docs/pbp-current-account/phase1/pbp-current-account-epics.md`

### Step 2 · BA reviews and refines
Open the generated file in Kiro editor. Use inline chat or direct edits to refine content. The agent will not mark any checklist items — that is the PO's job.

### Step 3 · BA triggers the PR hook
In Kiro chat, click the **Analysis Review** hook button (in the Agent Hooks panel) or type:
```
run analysis-review hook
```
The agent will ask for:
- Feature name → `pbp-current-account`
- PO GitHub username → e.g. `po-github-handle`

It will then automatically:
1. Create branch `features/pbp-current-account/epic-analysis`
2. Commit & push the phase1 folder
3. Open a PR and add the PO as reviewer

### Step 4 · PO reviews and merges
PO reviews the PR on GitHub, requests changes if needed, then merges.

### Step 5 · GitHub Action marks checklist complete
On merge, the `approve-analysis-checklist` workflow runs automatically and marks all items in the **Approval Checklist** section of the epic doc as `[x]`.

---

## Phase 1B — Story Generation & Approval

### Step 6 · BA generates stories
After epic checklist is fully approved (all `[x]`):
```
/sdlc-analyst #File:docs/brds/pbp-current-account-brd.md generate stories
```
The agent activates **Story Writer**, verifies the epic doc is approved, and creates:
`docs/pbp-current-account/phase1/pbp-current-account-stories.md`

### Step 7 · BA reviews and refines
Same as Step 2 — refine the stories document in Kiro.

### Step 8 · BA triggers the PR hook again
Same as Step 3. The agent detects the stories doc and uses branch suffix `story-analysis`.

### Step 9 · PO reviews and merges
Same as Step 4.

### Step 10 · GitHub Action marks stories checklist complete
Same as Step 5 — the checklist in the stories doc is marked `[x]`.

**Stories approval unblocks Phase 2 (Design/Architecture).**

## File Structure

```
docs/
├── brds/
│   └── pbp-current-account-brd.md          ← Input BRD
└── pbp-current-account/
    └── phase1/
        ├── pbp-current-account-epics.md     ← Generated by Epic Writer
        └── pbp-current-account-stories.md  ← Generated by Story Writer

.kiro/
├── agents/
│   └── sdlc-analyst.md                     ← @sdlc-analyst agent
├── skills/
│   ├── epic-writer.md                      ← Epic Writer skill
│   └── story-writer.md                     ← Story Writer skill
└── hooks/
    └── analysis-review.json                ← PR creation hook

.github/
└── workflows/
    └── approve-analysis-checklist.yml      ← Checklist auto-approval action
```

---

## Checklist Item States

| Symbol | Meaning |
|--------|---------|
| `- [ ]` | Pending — not yet reviewed/approved |
| `- [x]` | Approved — marked automatically by GitHub Action on PR merge |

> **Never manually edit checklist items** — they are the approval record for the SDLC audit trail.
