### US-001: Submit Current Account Application

**Epic:** EP-001 — Account Opening & Onboarding
**Feature:** EP-001-F01 — Account Application
**As a** customer
**I want to** initiate and submit a personal current account application online
**So that** I can open a bank account without visiting a branch

**Priority:** High
**Story Points:**

#### Acceptance Criteria (BDD)

```gherkin
Feature: Account Application Submission

  Background:
    Given the customer is on the account opening page
    And   the application form is available

  Scenario: Successful account application submission
    Given the customer has filled in all mandatory fields with valid data
    When  the customer submits the application
    Then  the application is accepted for processing
    And   the customer receives an acknowledgement notification via email and SMS
    And   the application is assigned a unique reference number

  Scenario: Application submission blocked by server error
    Given the customer has filled in all mandatory fields with valid data
    When  the customer submits the application
    And   a system error occurs during submission
    Then  the application is not submitted
    And   the customer is presented with an error message
    And   the customer is advised to retry or contact support
```

- [ ] Code implemented and unit tested
- [ ] AC scenarios automated (BDD)
- [ ] Code reviewed and merged
- [ ] QA sign-off obtained
- [ ] No open blocker bugs

#### Notes / Dependencies

- See US-002 for mandatory field validation behaviour.
- See US-006 for KYC document upload which follows this step.

  Scenario: Customer does not possess valid identification
    Given the customer has not provided any valid identification document
    When  the system performs eligibility validation

### US-007: Verify Customer Identity Against KYC Documents

**Epic:** EP-002 — Identity Verification (KYC)
**Feature:** EP-002-F02 — Identity Verification
**As a** compliance officer
**I want to** have the system automatically verify a customer's identity against their submitted KYC documents
**So that** KYC compliance is enforced consistently and efficiently without manual intervention for every application

**Priority:** High
**Story Points:**

#### Acceptance Criteria (BDD)

```gherkin
Feature: Identity Verification

  Background:
    Given the customer has uploaded at least one valid KYC document
    And   the document is queued for verification

  Scenario: KYC verification succeeds
    When  the system verifies the customer identity against the submitted document
    Then  the KYC status is updated to Verified
    And   the application proceeds to account creation
    And   the customer is notified that their identity has been verified
    And   the verification event is recorded in the audit log

  Scenario: KYC verification fails — document unreadable
    When  the system cannot read the submitted document
    Then  the KYC status is updated to Failed
    And   the application cannot proceed
    And   the customer is notified of the failure and prompted to re-upload
    And   the failure event is recorded in the audit log

  Scenario: KYC verification fails — identity mismatch
    When  the system detects a mismatch between the application details and the document
    Then  the KYC status is updated to Failed
    And   the application cannot proceed
    And   the customer is notified to contact support
    And   the failure event is recorded in the audit log

  Scenario: KYC verification service is unavailable
    When  the KYC verification service is unavailable
    Then  the KYC status is set to Pending
    And   the customer is notified of the delay
    And   the system queues the verification for retry when the service recovers
    And   the outage is recorded in the audit log
```
